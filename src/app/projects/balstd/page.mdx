# Two Wheel-Legged Balancing Robot

This project explores the control of a two-wheeled robot equipped with active suspension legs using optimal control techniques. Designed for the Robomaster/ARC robotics competitions, the goal is to keep the chassis as stable as possible while the robot navigates uneven terrain.


## Goal 

The robot is built on a custom two-wheeled drive base with 5-bar linkage suspension legs that can actively adjust for terrain or balance assistance. The control algorithm uses an LQR (Linear Quadratic Regulator) approach to maintain upright stability under disturbances.


## LQR Design

The LQR assumes a simplified 2d model of the robot that includes a wheel, rigid leg, and single hip joint, with torques applicable at each joint. Its state vector includes chassis pitch/velocity, wheel position/velocity, and pendulum angle/velocity. By driving this state to zero, it balances the robot.

The equations of motion were defined symbolically in a Matlab script, from which a symbolic solver was used to solve the nonlinear system model, linearize it into state space form, and finally solve the Discrete Algebraic Riccati Equation (DARE) to determine the LQR gain matrix.

### Gain Scheduling

This linearization is about a particular leg length. To avoid this restriction during operation, the gains were evaluated at a variety of plausible leg lengths and a 5th degree polynomial was fitted to each.

Ideally, the gain matrix would be solved symbolically in terms of the leg length allowing calculation of the exact values. However, this isn't easily accomplished in Matlab, so the polynomial approximation was settled for (after confirming the maximum error in the approximation had a negligable effect on performance). Now an appropriate gain set could be evaluated at the current leg length, ensuring good stabilization. 

## Simulation

Dynamic models of the robot were built in Simulink using Simscape Multibody to capture the true nonlinear dynamics of the leg and wheel mechanisms.

An initial 2d model was first created to test as close to the LQR as possible. There was a lot of debugging that had to be done with sign conventions and such, which was much easier to do with this reduced dimensionality.

This seemed pretty foolproof in simulation. It performed phenomenally against offset center-of-mass, incorrect torque scaling, and various initial states.
Notably however, it was still making other assumptions. Mainly, it was still a continuous-time controller (impossible with a microcontroller), and didn't model any sensor/motor delays and motor dynamics (torque ripple, etc.). 


## Deployment

The controller was deployed to a STM32-based embedded platform. Motor encoders were used for proprioceptive feedback, and a 6-axis IMU on the chassis was used for world orientation.

### Safety

Extreme caution was needed in early stages of testing, when the robot would likely freak out over small disturbances. To alleviate some of this responsibility, a "watchdog" system was implemented that would constantly monitor the robot state and trigger a "fall" mode (and an appropriate sound effect on the onboard buzzer) whenever anything looked amiss.

## Next steps

* Torque ripple compensation: From some tests I did, cogging torque seems to be making the commanded torque to the leg hip motors inaccurate. I'm working on compensating for this.
* Wheel hub motors: New motors should remove backlash issues in the wheel and make their control a lot smoother.
* Jumping: Ultimately I want this robot to be incredibly agile and take jumps/falls gracefully. The hip motors were spec'd to be more than powerful enough for this.
